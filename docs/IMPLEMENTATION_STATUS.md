## Implemented scope

The pnpm workspace contains React/Vite/Tailwind, Fastify, native SQLite/WAL with versioned embedded migrations and a stable Drizzle proxy adapter, official Octokit integration, deterministic diagnostics, and CI/container configuration.

### M1 connectivity follow-through

Automatic polling now measures its configured interval from the latest durable attempt as well as the last successful snapshot. Failed reads therefore wait the configured interval, including after restart; explicit operator retries remain immediate. This behavior is verified with synthetic time and a fixture client.

Connectivity hardening now covers conditional-cache authentication recovery, validator removal after a response stops providing an ETag, rejection of unexpected API redirects, and prevention of late responses restoring a disconnected client. Repository discovery returns an explicit completeness flag at its five-page/500-repository limit. Settings distinguishes unavailable installations and development PATs, displays incomplete discovery, and cancels stale discovery across mode/connection changes. Live discovery/add/sync requests after disconnection return an explicit conflict instead of silently accepting work that cannot run.

Synthetic HTTP integration coverage verifies authenticated discovery, partial-result propagation, sanitized upstream failures, disconnection without repository creation, and retention of selected repositories, warning/coverage metadata and the last successful timestamp across a failed sync and process restart. GitHub transport fixtures cover installation-token renewal, membership changes, permissions, pagination, retry/rate-limit handling and active/queued request cancellation. These are fixture checks, not additional real-installation acceptance. No GitHub mutations were performed.

The repository is public at [How-e/GitNostics](https://github.com/How-e/GitNostics); anonymous GitHub API and README reads confirmed public availability on 2026-10-18. The operator confirmed successful email delivery to the documented support mailbox on the same date. Mailbox delivery is operator-reported evidence; no test email was sent by the agent. [Integration readiness](INTEGRATION_READINESS.md) separately tracks App homepage/contact settings, hosted CI, and detailed read-only acceptance. Public source availability and a working support mailbox do not establish release readiness.

### M2 PR diagnostic follow-through

Check/status coverage and review coverage are now tracked independently. Approval deficits use review completeness, while incomplete requested-change evidence explicitly allows for a later superseding review. Explicitly incomplete per-PR evidence prevents automatic resolution of prior PR findings even when an aggregate collection flag claims completeness. Older cached snapshots remain supported.

An additive fourth migration preserves acknowledgment while a rule is temporarily suppressed, including across restart. Explicit manual lifecycle changes clear that remembered state. Fixture orchestration tests verify that incomplete sync retains acknowledged PR findings and that a later complete collection resolves absent findings. PR navigation exposes incomplete evidence independently of related findings and labels observations as diagnostic findings without asserting that each blocks merging.

These are deterministic implementation checks. Comparison with authorized live PR state, real token/permission recovery, and sustained polling behavior remain separate acceptance limits; no live GitHub writes are used to validate them.

### M3/M4 evidence and M6 recovery follow-through

Failed-job log sampling now reserves the first three eligible jobs in retrieved run/job order, independent of request completion order, and explicitly warns when further failed-job logs are omitted. `action_required` jobs are eligible. The persisted excerpt is a UTF-8-safe tail capped at 16 KiB after full bounded-download redaction, preserving terminal failures. Fixtures cover Unicode size limits, private-key boundaries, JWT redaction and signed-query credentials; redaction remains heuristic.

Storage fixtures verify known retained/expired totals, incomplete-sample exclusion, genuine zero, restart persistence and mode isolation. Invalid individual sizes and unsafe totals are rejected before replacing persisted data. Repository removal atomically deletes its scoped audit history as well as associated records, preserving other repositories, modes and global activity. Authorized live artifact inventory comparison remains open.

The compiled production smoke now restores an online backup with the service stopped, preserving the temporary active database and sidecars before replacement. SQLite integrity and foreign-key checks pass, recovered repositories/findings/settings match the backup, a later settings change disappears, and live/demo isolation survives restart. This uses disposable demo fixtures with zero GitHub requests; recovery of an actual private installation and off-host backups remains unverified.

Frontend route groups and charts load on demand with accessible loading/error states. A failed page download can recover by navigating to another route. The entry bundle is about 356 kB (113 kB gzip), with a separate 367 kB chart chunk and route groups of 14–26 kB. The build no longer emits its chunk-size advisory. Total transfer remains similar when every route/chart is visited; no sustained resource or universal latency claim is made.

## Limitations and remaining acceptance

- Demo fixtures never establish successful GitHub connectivity. Real App/public/private access is operator-confirmed. Token renewal, membership changes, and permission-failure behavior have fixture coverage but no separately recorded real-environment acceptance.
- The supported integration is one server-configured App installation. User OAuth/callbacks, multiple installations, multi-user accounts and hosted onboarding are not implemented. All live writes act as the installation; local operator authorization is separate.
- Rulesets/CODEOWNERS/workflow YAML are not exhaustively interpreted. Missing checks do not establish a path-filter cause, and missing permission never establishes a security regression. Unsupported/partial evidence remains visible and cannot automatically resolve earlier findings.
- Analytics describe bounded samples and local observation history, not exhaustive GitHub history or historical billing. Logs may be unavailable or exceed download limits. See documented calculations and bounds.
- Dispatch supports known workflow/ref without custom input fields. Use GitHub for input-dependent dispatches. Real reruns/deletions/dispatches need separate owner-controlled acceptance; no development test should mutate GitHub to close that gate.
- Webhooks and concrete AI/external notification adapters are not implemented. Core functionality has no AI/cloud dependency or telemetry.
- Frontend entry JavaScript is about 356 kB (113 kB gzip); route/chart splitting defers further downloads. Total transfer across all routes remains similar. No sustained resource, universal latency or all-day memory claim is made.
- Retention applies separately by mode to historical records and resolved findings, preserving current/active evidence. Backups have separate seven-file rotation and can retain removed metadata. Protect database/key directories and backups.
- Docker/Compose, CI, security headers and documentation are implementation evidence, not successful target-environment acceptance. For the current Windows local scope, complete remaining diagnostic/recovery/resource acceptance and hosted checks before a release-ready claim. Docker/Linux, remote TLS, and physical mobile acceptance are deferred until those deployment scopes are pursued.
